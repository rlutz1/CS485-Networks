## Web && HTTP

**process** -- program on host

within host, two processes talk with **inter-process communication**

processes on diff hosts chatting -- **messages**

**client processes** -- initiate communication

**server processes** -- process that waits to be contacted

**P2P** -- 2 clients that can talk to each other.

send through messages through socket (software layer to send out through items) -- socket the door out the house
+ to send, need ip address (other house number) and port number (identiable person you're sending to)

TCP/UDP -- *the highway to travel on*

HTTP message -- *the car on the highway*

both client and server have http layer (create message; receive and understand, issue response)

app layer protocol defines
+ types of message
+ message syntax
+ message semantics
+ rules for sending

open protocols -- open sources standard protocol that anyone can use.

proprietary protocols -- like, Zoom has its own special protocol for how they send messages

**securing TCP**

vanilla tcp and udp -- no encryption of data at all; raw text sent (including passwords lol)

*TLS* -- encrypted TCP connections; end-point authentication added to TCP!
+ TLS implemented in app layer
+ apps use TLS libraries that use TCP in turn
+ raw text is sent into the socket, encrypted text travels the internet
+ protocols have their own secure layer
  + see: HTTP: 80, HTTPS (TLS/SSL): 443 -- TODO: look more at this
