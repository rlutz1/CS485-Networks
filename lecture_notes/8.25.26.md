### network core functions

know that each router knows where it can send things

```
routing algorithms -> local forwarding table  --> header value and output link
```

+ **forwarding**: local action; move arriving packets to outgoing link correctly
  + looking up data in our local forwarding table
  + the small picture of where you're going within a city as you drive through it on your cross country road trip
+ **routing**: global action; determine source-destination paths
  + routing algorithms
  + find path based on all other packet switch's forwarding tables
  + looking at what interstates you're going to take on a drive across country
    + big picture general path

#### store-and-forward

+ **store-and-forward**: must wait for the *entire* packet to show up in full before pushing it to destination

+ packet transmission delay: takes L/R seconds to push out L-bit packet into link at R bps

+ **queueing**: queue up the packets to send next
  + queue's pile up when the transmission out is slower than the transmission rate in
    + when docs in rate is larger than out rate, wait in queue!!
    + without waiting, empty queue.
  + if queue is **full** anything arriving is lost -- *one instance of **packet loss***
  + typically FIFO queuing, may be specific to a scope otherwise, but typically just fifo
  + some switches send out a signal saying TOO FULL! to other switches as a way of **congestion control**


#### types of delay

1. **process**: reading packet meta, using table
2. **queue**: waiting in queue
3. **transmit**: the time to actually be sent out (how long to leave router)
4. **propagate**: time to travel to the next switch (how much time spent on link)

going down a water slide
+ trans delay: time to get through gate
+ prop delay: time to get down slide

**delay calculations likely on exam**
--> processing delay likely just given

+ **nodal delay**: all 4 delays summed
+ **end-to-end dealy**: sum of all nodal delays
+ **round-trip time**: $2 * endToEndDelay$
+ in casual conversation, combined delays == latency 

#### throughput

+ rate at which the destination receives data

+ **average throughput**: how fast something is downloading right now
+ **instantaneous throughput**: once its downloaded, the average time it took 
+ **bottleneck links**: the throughput will always run as fast as the slowest link on the path
  + a faster link can become a bottleneck with enough traffic

#### delay vs throughput

+ throughput -> the rate at which we send/get a packet of data over time
  + throughput is like how fast you can drive on the highway between A -> B to delive all the packages
+ delay/latency -> how long it takes we send/get the first piece of data
  + latency is like how long it takes you to get a single package from A -> B
  + measured by a ping command
